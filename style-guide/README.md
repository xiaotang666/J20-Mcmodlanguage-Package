# J20 翻译风格指南

> 本指南是翻译质量四维保障体系（语义/交互/文化/技术）的执行规范。所有译文必须遵守；Linter 自动检查的条目标注 ✅。

## 1. 语义层：消除机翻感

**意译优先、直译慎用**，拒绝逐词堆砌。

| 原文 | 劣质翻译 | 推荐译文 |
| --- | --- | --- |
| The Red Cedar Tree is a large tree that has magical properties. | 红柏树是一棵有魔法属性的大树。 | 高大无比的红柏树有着魔法的属性。 |
| Entity is not valid for placement here | 实体在此处放置无效 | 此处无法放置该对象 |

- 翻译前先了解模组背景、物品功能、界面布局，理解词条在语境中的含义；
- 生造词根据游戏内表现和词根拟译，无特殊含义可音译；
- 技术术语玩家友好化：`tick`→刻（首次加注"20刻=1秒"）、`chunk`→区块、`render distance`→视距。

## 2. 交互层：UI 空间与操作直觉

- **长度控制 ✅**：按钮/标签/提示语严格控制在原字符串 ±15% 长度内（Linter 对 ≤40 字符短文本告警）；
- **标点与空格 ✅**：优先半角标点节省像素空间；菜单项无空格连接（"世界生成设置"）；中英文之间加空格；
- **动词一致性**：操作按钮统一"动词+宾语"（"创建世界"/"导入存档"/"打开日志"，不要"开始创建"）；
- **格式代码与占位符保护 ✅（错误级）**：
  | 类型 | 示例 | 要求 |
  | --- | --- | --- |
  | 格式码 | `§a`、`&l` | 必须保留在对应文本两侧 |
  | 顺序占位符 | `%s`、`%d` | 可调换顺序（`%2$d`），数量必须一致 |
  | 命名占位符 | `{0}`、`%msg%` | 完整保留 |
  | 换行符 | `<br>`、`\n` | 保留 |
  | tellraw JSON | `{"text":"..."}` | 仅翻译 `"text"` 值 |

## 3. 文化层：黑话与彩蛋

- 机制黑话转译：`AFK`→挂机、`Chunk loader`→（生存服）常驻区块器、`Redstone contraption`→红石机关；
- 彩蛋可二次创作植入中文梗，但必须标注"创意译文"并保留原文对照；
- 遵循 Minecraft 标准译名（zh.minecraft.wiki），除非与模组语境/代码冲突。

## 4. 技术层：术语库与翻译记忆

- **三级术语库**（`glossary/`）查询优先级：`<modid>.json` → `mods.json` → `vanilla.json` → zh.minecraft.wiki；
- 术语违规 Linter 自动告警 ✅；同一术语跨模组不同译法时以模组专属术语优先；
- **翻译记忆**：用 OmegaT 管理，`project_save.tmx` 导出到 `tm/<modid>.tmx`；
- 模糊匹配阈值：100% 直接复用；85–99% 快速确认；70–84% 参考修改；<70% 重新翻译；
- **TM 一致性 ✅**：相同原文在不同文件中译文必须一致（Linter 告警）。

## 5. 敏感词 ✅

自动拦截低质网络用语（脑残/傻逼/尼玛等），触发即警告并人工确认。

## 6. AI 辅助翻译守则

- AI 只做初稿，**必须经人工审核**（走 待审核/ 工作流），不得将 AI 输出直接提交给模组作者或直接入库；
- 保留占位符/格式码由工具强制校验；
- 技术串（ID、布尔值、纯数字、snake_case、命名空间 ID）自动跳过不翻译；
- 提示词中带术语库约束，优先复用 TMX 已有翻译。
